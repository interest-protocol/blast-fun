# React hooks library adoption

Verified against current official documentation, tagged source, and the live npm registry on 2026-10-14. Version, peer dependency, dependency, and publication facts below come from the registry rather than search snippets. Hook behavior was checked against the published package artifacts; application regression checks are reported separately.

## Recommendation

Adopt **`@mantine/hooks` 9.7.2**, using named imports directly where their semantics match existing behavior. It is standalone: no Mantine components, provider, CSS, or runtime dependencies are required. Its React peer is `^19.2.0`, which includes this workspace's React 19.2.8 and 19.3 applications. The published ESM and CommonJS builds include TypeScript declarations, `sideEffects: false`, and client directives. The project shipped six stable versions between September 9 and October 11, 2026. This makes it the strongest current maintenance and React-version fit among these candidates. [Standalone package documentation](https://mantine.dev/hooks/package/), [published metadata and release timestamps](https://registry.npmjs.org/@mantine%2fhooks), [release history](https://github.com/mantinedev/mantine/releases)

The tradeoff is a larger hook catalog than we need, a React 19.2 minimum, and APIs that are not interchangeable with every local effect. Tree shaking limits shipped code, but it does not prove a particular bundle-size saving. Keep domain orchestration, validation, accessibility handlers, and browser fallbacks when migration changes their contract.

## Workspace inspected

`web` uses Next.js 16.3.1, React/React DOM 19.2.8, TypeScript 6.0.3, and React 19 types. `boosts-alpha` uses Vite 8, React 19.2.8, and TypeScript 6. `admin-acl` uses React 19.3 and TypeScript 7. These are separate applications under a container directory; generated outputs, vendored sources, and alternate worktrees are not additional production migration targets. No hooks collection was already declared in these applications. Existing React hooks and browser effects must be assessed individually, particularly in the SSR-rendered Next.js application.

The supplied host-wide memory budget applies. `web/AGENTS.md` additionally requires reading the installed Next.js documentation before changing relevant code, preserving SDK boundaries, and consulting interface guidance before UI changes.

## Equivalent hooks and migration constraints

| Existing functionality | Mantine equivalent | Contract to preserve |
| --- | --- | --- |
| Trailing debounced state/props | `useDebouncedValue(value, wait)` | Initial value remains immediate; changes supersede pending timers; same wait; cancel on unmount. Do not replace network race guards or staged form validation. |
| Debounced callbacks | `useDebouncedCallback` | Verify leading/trailing, flush, argument retention, and unmount behavior against actual caller; value debounce is simpler for controlled search. |
| Fixed repeating UI clocks | `useInterval` | Default does not start; `autoInvoke` starts on mount but does not call immediately. Verify StrictMode, cadence, cleanup, and delay changes before replacing a raw interval. Its stateful start/stop is more involved than a raw timer. |
| One-shot timers | `useTimeout` | `start()` ignores calls while already pending; it is not a resettable timeout. Preserve copy-feedback resets, step-dependent timers, deadlines, polling/backoff, and recursive timers locally. |
| Window DOM listeners | `useWindowEvent` | Listener uses React 19.2 `useEffectEvent`, keeping current callback. Preserve target, propagation, key filtering, capture/passive, and enabled periods. Options are not an effect dependency: use only when fixed. |
| Element DOM listeners | `useEventListener` | Returns a callback ref instead of taking an arbitrary document/element target. Do not change document-target listeners or conditional attachment solely to use it. |
| Arbitrary media queries | `useMediaQuery(query, initialValue)` | Default defers read to passive effect; explicit initial `false` matches false SSR state. Immediate client reads require `getInitialValueInEffect: false`, which can mismatch SSR. Published version uses modern `addEventListener` only. |
| Reduced motion | `useReducedMotion(initialValue, options)` | Same media implementation; preserve whether preference updates in passive effect or must be read before animation starts. Retain legacy listener fallback when required. |
| Local/session storage state | `useLocalStorage` / `useSessionStorage` | Default JSON encoding and cross-tab/same-document sync can differ from raw `on`/`off`, expiry-validated drafts, transaction journals, and cache schemas. Hook initialization may write the restored/default value. Keep trust-boundary parsers and storage ownership. |
| Single element intersection | `useIntersection` | Starts with `entry: null`, returns callback ref, disconnects on target/ref changes. No missing-API fallback; does not implement multi-element observation or freeze-once semantics. |
| Element size | `useResizeObserver` / `useElementSize` | Starts at zero; uses animation-frame batching, box sizes where supplied, and callback-ref cleanup. Not an exact substitute for immediate `getBoundingClientRect` measurements or an effect with a missing-observer fallback. |
| DOM mutation observation | `useMutationObserver` | Preserve target/subtree/attribute options and synchronous initial state read. Ref API does not automatically replace observing `document.body` and combining pointer/media listeners. |

Sources: [debounced value docs](https://mantine.dev/hooks/use-debounced-value/), [interval docs](https://mantine.dev/hooks/use-interval/), [timeout source](https://github.com/mantinedev/mantine/blob/9.7.2/packages/@mantine/hooks/src/use-timeout/use-timeout.ts), [window event source](https://github.com/mantinedev/mantine/blob/9.7.2/packages/@mantine/hooks/src/use-window-event/use-window-event.ts), [media docs](https://mantine.dev/hooks/use-media-query/), [storage docs](https://mantine.dev/hooks/use-local-storage/), [intersection docs](https://mantine.dev/hooks/use-intersection/), [resize observer docs](https://mantine.dev/hooks/use-resize-observer/), [published package source](https://registry.npmjs.org/@mantine/hooks/-/hooks-9.7.2.tgz).

## Verification priorities

Test the migrated callers rather than only the dependency: debounce timing after rapid changes and unmount, stable server/initial client values, media listener cleanup and preference updates, timer cadence without resets on renders, and keyboard behavior with fresh state and preserved default prevention. Exercise StrictMode for library lifecycle behavior. No observer/storage migration is justified merely by similar names; retain existing code when timing, format, fallback, or ownership differs.

Do not describe peer-version acceptance as proof of compatibility, or `sideEffects: false` as a measured bundle reduction. Full browser, legacy browser, and production-bundle verification remain separate checks.
